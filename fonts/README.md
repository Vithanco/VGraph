# Bundled fonts

DM Sans, subset and instanced for the renderers that cannot fetch it themselves.
Generated by `scripts/build-fonts.sh` — edit that, not these files.

## Why these exist

A browser opening one of our SVGs gets DM Sans from the `@import` that
`SVGBuilder.dmSansFontImportCSS()` writes into `<defs>`. Nothing else does:

- Rasterisers don't fetch stylesheets. `rsvg-convert` and resvg both ignore the
  `@import` entirely.
- resvg also ignores an `@font-face` embedded in the SVG as a data URI — the
  same SVG with a base64 DM Sans inlined and with no font information at all
  render byte-identically, text missing. Inlining is not a way out.

So every non-browser consumer needs the faces as files: the Docker image
(`fontconfig` + `rsvg-convert`) and the local MCP server in `vgraph-mcp-node`
(resvg).

## Why TTF, and why one file per weight

Both learned by testing, not from documentation:

- **TTF, not woff2.** resvg-wasm panics (`RuntimeError: unreachable`) on DM Sans
  italic as woff2 — including Google's own unmodified file. The same face as TTF
  is fine. Fontconfig wants TTF anyway.
- **Static instances, not the variable font.** resvg ignores the weight axis:
  one variable file renders 400, 500, 600 and 700 identically, so the weights
  `VSVGNode` asks for would silently come out regular.

## Why the build script renames them

Upstream calls this family **DM Sans 9pt** — v4 is an optical-size family, and
the instancer preserves that name. Our SVGs ask for `DM Sans`, which never
matches it, so shipping the faces unrenamed puts them on disk where fontconfig
will happily list them and rsvg-convert will still substitute. Verified the
hard way: with the original names, rendering with and without the fonts
installed produced byte-identical PNGs.

The instancer also leaves every weight's style name as `Regular`, so the four
roman files are indistinguishable to anything matching on names rather than
`OS/2.usWeightClass`.

## What this does *not* fix

The graph title asks for bare `Helvetica` and the watermark for bare `Arial`
(`Attributes.Group.fontname` defaults to `.helvetica` rather than to
`FontFamily.default`). Those are not DM Sans and are not fixed by anything in
this directory — the Docker image installs `fonts-liberation` for them.

## Coverage

ASCII, Latin-1 accented letters, and the punctuation labels realistically carry.
A character outside that set falls back to another face rather than rendering in
DM Sans — widen `CHARSET` in the build script if that shows up in practice.
