Timeline Notation — column-guide treatment

Implementation brief: replace the current event-like rendering of TimePoint nodes with an axis-and-guide treatment. The Timeline notation gains a dedicated visual vocabulary that distinguishes temporal coordinates from events.

01 · Problem

Why this change

In the current renderer, TimePoint nodes use the standard Notation §02 node pattern — rounded rect, type label, content, icon disc. That pattern says "this is a thing." But a timepoint isn't a thing; it's a coordinate on an axis. Events are things that happened at a coordinate.

The pattern mismatch has two effects: timepoints visually compete with events for attention, and the alignGroup mechanic (events aligning vertically under their timepoint) is rendered but invisible — there's no visual evidence that "Industrial Revolution peaks" sits in the 1850 column.

Before — timepoints as nodes
After — axis + descending guides
02 · Visual specification

Two new render layers

The Timeline notation introduces two render layers the renderer doesn't currently have. Neither requires DOT changes — they're post-layout drawing passes on top of what Graphviz already returns.

A. Axis anchors (replaces TimePoint node render)

Glyph3px filled circle, axis-baseline color
LabelYear string only — no "TIME" type label, no rounded rect, no icon disc
Label fontDM Sans, 12px, 500, ink-primary
Label positionCentered below the dot, 14px from the axis baseline
Axis baselineHorizontal rule connecting all anchors, 1px, ink-2 @ 0.4 opacity
Sequence arrowsExisting — unchanged. The Graphviz sequence edges between TimePoints are still drawn as standard edges.

B. Column guides (new draw pass)

GeometryVertical line at x = timepoint.cx, from axis baseline to diagram bottom
Stroke1px, ink-2 @ 0.35 opacity light / 0.30 opacity dark
Dashstroke-dasharray: 2,4
Z-orderBelow group containers, above page background. See §04.
Pass-throughGuides render continuously through group container backgrounds. Group fills are opaque enough to mask them slightly — that's intentional (guides feel like wallpaper, not foreground).
TerminationStop at the bounding box of the last group containing a member of that alignGroup. If no events use the column, guide still draws full-height (useful for empty-column hint).
Why guides at all. The alignGroup mechanic already positions events under their timepoint. The guides make that mechanic visible — a reader can trace from a timepoint label down to every event in that year without eye-measurement. They're not decoration; they're the visual encoding of the Timeline data model.
03 · Tokens to add

Light → dark mapping follows §11's existing role-preserving pattern. Opacities are tuned slightly differently per mode because light-on-dark needs marginally less opacity to feel as present as dark-on-light.

04 · Graphviz integration

No DOT changes needed

Everything Graphviz needs to give us, it already does. The new work is entirely in the custom renderer's post-layout passes.

Input from GraphvizHow it's used
Per-node pos attribute (center X, Y) Read timepoint.cx for guide X position and anchor dot placement.
Root graph bb attribute Read diagram bottom Y; guides span from axis baseline to bb.y2.
Existing sequence edges between timepoints Rendered as standard edges. Unchanged.
Existing alignGroup constraints Unchanged. Whatever mechanism currently aligns events under their timepoint X still applies. The guides simply visualize what's already true.

Render-order requirement (critical)

The renderer's existing draw order needs one new layer:

// New layer order (top-to-bottom = back-to-front):
1. Page background
2. Column guides            ← NEW · only for Timeline notation
3. Group containers (fill + dashed border)
4. Axis baseline + anchor dots  ← NEW · only for Timeline notation
5. Edges (with arrows)
6. Nodes (events)
7. Edge labels
8. Watermark

Guides go under group containers so they feel like a structural backdrop. Axis baseline + anchor dots go above groups so they read as the top-level coordinate system. Both new layers render only for diagrams of notation type Timeline.

05 · Render algorithm

Drop-in pseudocode

// After Graphviz layout completes, before drawing anything else:

function renderTimelineChrome(graph, svg, theme) {
  if (graph.notation !== 'Timeline') return;

  const timepoints = graph.nodes.filter(n => n.type === 'TimePoint');
  const bb = graph.boundingBox; // from Graphviz

  // Sort by X so the baseline draws left-to-right
  timepoints.sort((a, b) => a.cx - b.cx);

  const axisY  = timepoints[0].cy;
  const diagramBottom = bb.y2 - 16; // small bottom padding

  // PASS 1 · Column guides (lowest layer, before groups)
  for (const tp of timepoints) {
    svg.layer('guides').line({
      x1: tp.cx, y1: axisY + 10,
      x2: tp.cx, y2: diagramBottom,
      stroke: token('--timeline-guide', theme),
      strokeWidth: 1,
      strokeDasharray: '2,4',
    });
  }

  // ...groups render here in normal order...

  // PASS 2 · Axis baseline + anchor dots (above groups, below edges)
  const xs = timepoints.map(t => t.cx);
  svg.layer('axis').line({
    x1: Math.min(...xs) - 20, y1: axisY,
    x2: Math.max(...xs) + 20, y2: axisY,
    stroke: token('--timeline-axis', theme),
    strokeWidth: 1,
  });
  for (const tp of timepoints) {
    svg.layer('axis').circle({
      cx: tp.cx, cy: axisY, r: 3,
      fill: token('--timeline-axis', theme),
    });
    svg.layer('axis').text({
      x: tp.cx, y: axisY + 22,
      anchor: 'middle',
      font: 'DM Sans 12 500',
      fill: token('--timeline-year', theme),
      content: tp.label, // the year string
    });
  }
}

// In the main render dispatch:
function renderNode(node, svg, theme) {
  if (node.type === 'TimePoint') return; // drawn by renderTimelineChrome
  // ...existing node rendering...
}
06 · Edge cases & rules

Things to handle

Timepoints not horizontally aligned Use the median Y of all timepoints for axisY. Don't try to draw a curved or stepped axis baseline.
Only one timepoint Skip the axis baseline (degenerate). Draw the anchor dot, label, and a single guide.
Zero events on a column Guide still draws full-height. The empty column itself communicates "no event here" which is data, not absence.
Events outside any alignGroup Render normally. Guides only correspond to declared timepoints — events without alignGroup just sit where Graphviz puts them.
Nested groups (e.g. region → country) Guides pass through nested group fills the same way they pass through top-level groups — z-order is "below all groups," not "below outermost group."
Sequence edge crosses a guide No collision logic needed. Edges (z=5) render above guides (z=2), so the edge wins visually. Guides are wallpaper.
Do not let timepoint nodes render via the standard Notation §02 node pipeline as well. The dispatch must short-circuit on type === 'TimePoint' — otherwise you'll get a phantom rounded rect underneath the new axis treatment. This is the most likely regression source.
07 · Acceptance criteria

How we know it's done

  • Visual: timepoints don't look like events. No rounded rectangle, no type label, no icon disc on any TimePoint node.
  • Visual: axis baseline is present. A horizontal rule connects all timepoint dots, with 20px overhang on each side.
  • Visual: column guides descend through the diagram. From each timepoint dot down to the diagram's bottom edge, dashed, at correct opacity.
  • Layering: guides are behind group containers. When a group's fill overlaps a guide, the fill is on top. (Will look slightly "muted" in the overlap — that's correct.)
  • Alignment: events sit on their guide. Any event with alignGroup: "1850" is horizontally centered on the 1850 guide. (Already true via existing alignGroup logic; this verifies the guide line draws at the same X.)
  • Dark mode: all three tokens swap correctly. Axis, guides, and year labels remap via §11. No literal light-mode hex remains in the rendered SVG.
  • Other notations unaffected. Render a CRT, IBIS, BBS, etc. — no axis baseline, no guides, no behavior change. The new code path is gated on notation === 'Timeline'.
  • VGL source is unchanged. The example timeline from the demo (vgraph myTimeline: Timeline …) renders correctly without any edit to its VGL source.
08 · Out of scope

Not in this brief

  • Era bands / colored regions between timepoints. A future enhancement could shade alternating columns. Not needed for the v1 treatment.
  • Curved or non-linear axes. Logarithmic time scales, branching timelines, etc. — out of scope.
  • Timepoint hover/interaction behavior. This is a static-render spec. Interaction belongs to the host app, not the diagram renderer.
  • Updates to other notations. The §02 Notation node pattern still applies to every notation other than Timeline.
